## Preview and export behavior

- Every text file is rendered in a native `<details>` disclosure. Its content is assigned through `textContent`, not HTML parsing.
- Preview text is searchable, selectable, keyboard-focusable, and labeled with an exact UTF-8 byte size and mode badge.
- The field-by-field exposure table is generated from the same mode used to generate the report files and is itself included as `data-exposure.json`.
- ZIP entry paths are normalized and de-duplicated before the report is returned to the UI. Dot segments are removed after trimming, Windows-unsafe characters/device names are neutralized, and preview/ZIP creation consume the same normalized array.
- The regression gate parses the generated uncompressed ZIP and compares every entry path and decoded content with the preview array. Equality passed.
- Export recomputes the file digest and asks the service worker to compare source tab/revision, scan projection, candidate state, queue/history, settings, permissions, diagnostics, and sensitivity with the preview context.
- UI listeners invalidate the preview on navigation/reset, candidate replacement/merge, queue broadcasts, local settings/diagnostic/history storage changes, explicit clears/resets, rescan/state refresh, and sensitivity changes.
- If anything changes while validation is running, the UI identity check blocks the export and requires a new preview.
- Preview data remains only in the open extension page's memory. The extension does not retain exported ZIPs; browser/OS download retention is user-controlled and the UI instructs the user to delete files manually when no longer needed.

## Residual limits

- Correlation values are non-cryptographic identifiers intended only to compare entries inside a local report; they must not be described as anonymization.
- Sensitive URL mode intentionally exposes identifying context after informed confirmation. It is not a privacy-safe sharing mode merely because credential and secret-shaped values remain redacted.
- Browser rendering, keyboard behavior, zoom, forced-colors behavior, and screen-reader announcements require the P1 clean-profile browser and accessibility matrix before publication readiness can pass.
